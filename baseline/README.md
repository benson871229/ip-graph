# 流量 Baseline — 依服務彙總

建立網路流量基準,讓之後**只需要看「新增」的那幾列**,不必每天重看整張圖。

跟 `graph/ip-graph.html` 是**兩件獨立的事**:關聯圖是用來調查單一事件的,
這裡是用來建立與維護長期基準的。

---

## 為什麼從服務出發,而不是從 IP 出發

baseline 要有意義就必須細到 port,但**不可能針對每個 IP 去看它連了哪些 port** ——
幾百個 IP 乘上各自的 port,是做不完的工作。

解法是把問題轉 90 度:

> IP 有幾百個,但**實際在用的服務埠只有幾十個**。
> 不要問「每個 IP 用了哪些 port」,改問「**每個服務是誰在用**」。

再把 IP 收斂成網段,一份幾百個 IP 的網路就變成大約 **60–150 列**:

| 判定 | 服務 | 來源網段 | 目的網段 | 來源台數 | 目的台數 |
|---|---|---|---|---|---|
| ⚠僅1台 | 8291/tcp | 10.20.0.0/24 | 外部 | 1 | 1 |
| ⚠高風險 | 3389/tcp | 10.20.0.0/24 | 10.20.0.0/24 | 1 | 1 |
| ⚠高風險 | 445/tcp | 10.40.0.0/24 | 10.30.0.0/24 | 62 | 3 |
| | 104 dicom | 10.20.0.0/24 | 10.30.0.0/24 | 8 | 2 |

**port 的細節一個都沒少,但你完全不必逐 IP 看。** 而且這是資安人腦袋本來的運作方式:
你要問的是「這個服務該不該存在、誰該用它」,不是「這台機器做了什麼」。

異常會自己浮出來 —— **只有 1~2 台在用的服務,不是特例就是有問題**,
所以排序刻意把「有標記的」和「來源台數少的」放最前面。

## 取數

在 **Security Onion 主機**上跑,產出的 CSV 拿回 Windows 用 Excel 開。

```bash
# 產生基準(建議一次吃 7 天)
./make-baseline.sh /nsm/zeek/logs/2026-07-*/conn*.log* > baseline-2026-07.csv

# 之後每週比對:只印出基準裡沒有的列
./make-baseline.sh -c baseline-2026-07.csv /nsm/zeek/logs/current/conn.log
```

| 選項 | 說明 |
|---|---|
| `-c FILE` | 比對模式,只輸出基準 `FILE` 沒有的列 |
| `-p 24` | 網段粒度,`24`(預設)或 `16` |
| `-h` | 說明 |

**不需要 `zeek-cut`** —— SO 2.4 的 Zeek 跑在容器裡,主機不一定有。
腳本直接讀 conn.log 的 `#fields` 表頭自己對欄位,所以欄位順序改版也不受影響。
支援 `.log` 與 `.log.gz`,可一次吃多個檔。

**觀察窗要滿 7 天。** 少於一週,那些每週只跑一次的備份、報表、對帳作業
會在下次比對時被當成「新增」。

## 怎麼審

打開 CSV,**用第一欄「判定」排序或篩選**。空白的是例行流量,可以整批略過;
有標記的才需要看。腳本會預先標三種:

| 標記 | 意思 |
|---|---|
| `⚠高風險` | 埠落在遠端控制 / 檔案共享 / 明文管理 / 常見後門清單(RDP、SMB、SSH、Telnet、WinRM、VNC、4444…) |
| `⚠僅1台` | 只有 1 台來源在用 —— 不是特例就是異常 |
| `對外` | 目的是外部網段 |

對每一列問三個問題:

**1. 這個服務該不該存在?**
`8291/tcp`、`4444`、`31337` 這種在醫療網路裡沒有正當理由的,直接查。

**2. 誰該用它?**
RDP 只該從維運網段發起;DICOM 只該從 modality 到 PACS。
**來源網段對不對,比服務本身更重要** —— 445 SMB 從辦公網段到檔案伺服器是正常的,
從醫療設備網段到醫療設備網段就不是。

**3. 使用的台數合理嗎?**
1 台用 = 特例或異常;60 台用 = 通用服務,反而正常。
數字突然改變(本來 3 台變 30 台)比數字本身更值得注意。

審完在旁邊自己加一欄註記,存檔 —— **這份 CSV 就是你的 baseline**。

---

## 每週例行

```bash
./make-baseline.sh -c baseline-2026-07.csv /nsm/zeek/logs/current/conn.log
```

只會印出新增的幾列。確認沒問題的,把該列補進 baseline CSV;有問題的就是事件。

設備汰換或網段調整之後要重新產生基準,否則舊網段會一直留在表裡。

---

## 這套 baseline 的界線

它記錄的是**「觀察到的現況」,不是「應該有的樣子」**。

第一次產出的表裡,本來就可能包含既有的設定錯誤、違規的遠端存取、
甚至已經存在的入侵。**審核那一步不能跳過** —— 如果直接把第一次的輸出當成基準,
等於把現有的問題正當化,之後永遠不會再被標記出來。

其他限制:

- **只看得到 Zeek 看得到的流量**。沒有經過感測器的網段(例如同一台交換器內的
  同 VLAN 流量)不會出現在裡面。
- **失敗的連線被刻意排除**(`S0` / `RSTOS0` / `SH` / `REJ`)。
  這些是掃描與探測的產物,不代表服務真的被使用。要找掃描請用
  `hunting/threat-hunting-kql.md` 的 B3。
- **外部位址全部歸成一組「外部」**。這是為了讓表保持簡潔 ——
  幾千個外部位址會把表撐爆。審核時看的是「哪個服務對外」,
  要追是對到哪個 IP,再回頭用關聯圖或 Kibana 查。
